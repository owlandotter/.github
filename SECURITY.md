# Security policy

This policy covers everything Owl & Otter runs: owlandotter.app, the API, the dashboard, the SDKs and every repo in this organisation.

## Reporting a vulnerability

Please don't open a public issue, pull request or discussion for a security problem.

Report it privately through GitHub instead:

1. Go to [Report a vulnerability](https://github.com/owlandotter/.github/security/advisories/new).
2. Describe the problem, where you found it and how to reproduce it.

Most of our repos are private, and GitHub only offers private reporting on public repos, so this one form takes reports for all of them. If you can't use it, email [support@owlandotter.app](mailto:support@owlandotter.app) with "Security" at the start of the subject line.

A useful report includes:

- The affected URL, endpoint, SDK or repo
- Steps to reproduce, or a proof of concept
- What an attacker could do with it
- Any account or tenant IDs you used while testing

## What happens next

Owl & Otter is run by one developer, so there's no security team or fixed response time. We'll confirm we've got your report, keep you posted while we work on it, and tell you when it's fixed. If you'd like credit in the advisory, say so and tell us the name to use.

## Testing guidelines

- Only test against accounts and tenants you own.
- Don't access, change or delete other people's data. If you hit some by accident, stop and tell us.
- Don't run denial of service tests, spam, or social engineering against us or our customers.
- Give us a reasonable chance to fix the problem before you talk about it publicly.
